# DocuSign Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: офис-менеджер/
юрист/sales-ops, отвечающий за оборот подписываемых документов.

## 1. Credential type
JWT Grant, multi-secret: `environment` (demo/production) + `integration_key` +
(RSA private key + user_id, судя по JWT Grant flow — уточнить по schemas.py полностью).
Самый сложный auth-класс в портфеле — требует предварительной генерации RSA-пары на
стороне DocuSign admin panel ДО того, как пользователь вообще может подключиться.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` с ЧЕСТНЫМ предупреждением: "Подключение DocuSign
   требует 3 шага на стороне DocuSign Admin ДО возврата сюда" + пронумерованный
   чек-лист этих шагов (создать Integration Key, сгенерировать RSA-пару, дать consent) —
   идеально в виде `Accordion` с раскрывающимися инструкциями на каждый шаг, а не
   единым абзацем текста.
2. **Environment toggle** — demo/production ДО ввода ключей, т.к. Integration Key
   привязан к конкретному окружению.
3. **Consent step** — JWT Grant требует одноразового user consent через браузер
   (отдельный от нашего OAuth) — идеально: отдельная кнопка "Дать согласие в DocuSign"
   (`ui.Open`), с чётким объяснением "это отдельный шаг, без него токены не будут
   выпускаться", и явной проверкой статуса после возврата.
4. **После успеха** — сразу видно `audit_account_health` (см. POST_CONNECT_EXPERIENCE).
5. **Ошибка "consent_required"** — конкретный, узнаваемый алерт с прямой ссылкой на
   повторный consent-URL, не общий "не удалось подключиться".
6. **Истечение JWT** — JWT Grant токены обычно живут долго, но private key может быть
   отозван на стороне DocuSign — идеально: отдельное состояние "ключ отозван" (не путать
   с "истёк") с инструкцией перегенерировать RSA-пару.
